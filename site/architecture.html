Architecture / Authority Separation

Probabilistic input. Deterministic acceptance.

KAD-PI treats models as bounded interpreters and assistants. They can produce candidate proposals and execute scoped work; they cannot unilaterally mutate canonical state or grant themselves acceptance.

02 / Architectural Planes

Five strictly separated execution boundaries.

PLANE 01

Canonical Knowledge Vault

Human-editable Obsidian Markdown vault (vault/) structured into explicit authority zones (Governance, Corpus, Research, Systems, Archive). The single durable source of truth.

PLANE 02

Projection Compiler

Deterministic compiler (bin/kad-wiki rebuild) transforming canonical notes into typed projections for Sofia, the public site, README, and downstream tools with cryptographic provenance.

PLANE 03

Workpackage Engine

Deterministic state machine (workctl) governing claims, mutating locks, preflight verification, execution scopes, test requirements, and transition gates.

PLANE 04

Observatory & Telemetry

Append-only tamper-evident causal journal tracking actual vs shadow economic routing decisions, token usage, and execution telemetry without altering production authority.

PLANE 05

Presentation Interfaces

Read-only observation surfaces: the Sofia v3 Cockpit for local interactive graph exploration, and the static public site for architecture briefs and public research dissemination.

INVARIANT

Zero Back-Propagation

No presentation surface, browser script, or AI assistant can write directly to canonical state without passing through the workpackage claim, review, and verification gate.
