# Final Report — WP-KAD-MEMORY-SUBSTRATE-057

**Status**: implemented and verified, with three qualified criteria recorded in `acceptance-receipt.json`.
**Base commit**: `3a0b5b0f2cb11ed00b65ef8da7bb49c309c42af5` (no commit made)

## What changed

### One memory record instead of three surfaces

ai-memory 2.1.1 is now the wiki of record. It owns a git-backed markdown corpus at
`/home/amdy/Work/.ai-memory/wiki/01a090eb-…/01a090eb-…/` and a rebuildable SQLite index, and it runs as a
systemd user service on `0.0.0.0:49374` behind a bearer token so other hosts on the LAN can attach.

`vault/` became its **deterministic mirror** — regenerated by `bin/kad-memory publish`, committed so a
clone, CI and the remote keep the knowledge without the substrate running. The publish path uses
`ai-memory export-okf` as a conformance gate and `rsync` as the mirror, because the export bundle carries
markdown only while the mirror must also carry the derived JSON the repository regenerates. That gate earned
its place immediately: it refused every publish until 16 pages whose frontmatter was invalid YAML were
repaired.

Every mutating vault command now **fails closed** against the mirror. `vaultRoot()` resolves
`KAD_VAULT` → record pointer → `<cwd>/vault`, and `assertCanonicalRoot` refuses `ingest`, `propose`,
`approve`, `apply` and `rebuild` when they would write to a tree the next publish destroys. Read-only
commands still work against the mirror so a fresh clone validates.

Obsidian points at the record, not the mirror, so human editing lands on the canonical surface.

### OpenViking retired, replaced by a non-authoritative adapter

`tools/kad/research-openviking.mjs` and its test are gone. `createAiMemoryAccessAdapter` returns
`authority: false`, marks every record `acceptance_state: PROPOSED` with a `source_ref` and `source_hash`,
and — importantly — **degrades instead of throwing**: an unreachable substrate, a 401, or a missing token
yields a `DEGRADED` probe, an empty search and a null read, so a retrieval outage can never break the
KnowledgePlane. Nine offline tests pin those invariants, including the one that matters most: the adapter
cannot emit `ACCEPTED`.

The two `config/` registry entries that still named OpenViking are marked `RETIRED` rather than deleted —
they record what was evaluated. Historical references under `evidence/**` and `.agents/work/**` (83 files)
were deliberately left alone.

### One gateway endpoint for models

OmniRoute 3.8.50 runs as a systemd user service on `127.0.0.1:20128`, registered as `TRANSPORT_ONLY`:
registering a connection grants reachability, never qualification. Local KAD GGUF endpoints are proxied
while admission and lifecycle stay with `bin/kad-serve`.

`bin/kad-models sync` snapshots the gateway catalog into a hash-verified file, is idempotent, and refuses to
write when the gateway is unreachable or empty rather than erasing the previous snapshot.

The harness projection is bounded by `config/omniroute-exposure.json`: **1610 advertised models reduced to
31 exposed**. Only local endpoints, the operator's already-paid subscriptions, and explicitly free-tier ids
reach OMP; metered models are excluded, so no fallback chain can generate an unapproved bill. The full
advertised set stays in the snapshot for auditability.

OMP now reports `omniroute (31)`.

## The one thing worth arguing about

**The spend gate and the config have been diverging for a while, and nothing noticed.**

`tools/kad/omp-orchestration-preflight.mjs` reports `BLOCKED` **at pristine HEAD**, before any of this work:
its spend predicate demands that every `enabledModels` pattern resolve to a loopback `auth: none` provider,
while the project's config has always enabled subscription providers (`google-antigravity/*`,
`opencode-codex/*`, `opencode-go/*`, `zai-free/*`). The gate is not wrong to want that; the config is not
wrong to enable subscriptions. Nobody reconciled them, so the gate has been reporting a condition everyone
ignored — which is how a real violation would hide.

This workpackage does not fix that, and deliberately does not weaken the predicate. What it does add is a
*finer* control: `config/omniroute-exposure.json` bounds which **models** are reachable, not merely which
providers are enabled, and is auditable and hash-recorded. Reconciling the preflight predicate with the
subscription policy is a governance decision that belongs to the operator.

## Pre-existing conditions, proven not introduced

- `bin/kad-wiki lint` reports 126 errors, `rebuild` refuses to run. All 126 are on files with **zero git
  tracking at the cutoff** — verified per file against `git ls-files`. They are an uncommitted research and
  Gaya corpus that never satisfied the vault schema. The WP did **not** mint `kad_id`s or invent
  `authority` / `epistemic_class` / `review_status` for unreviewed research material: that would be exactly
  the silent promotion to canonical that the new ISA forbids. It is a content decision.
- `local-multi-endpoint.test.mjs` T2–T4 fail identically against a pristine `git archive HEAD` export
  (`BLOCKED` vs `DEGRADED`). T1/T2/T6 pinned array positions, which concurrent `zai-free` additions broke;
  those three were decoupled from index order and T1b was added to assert the new transport-only invariant.
- The tree carried 348 dirty paths at claim time, from workpackages running in parallel. All of this work is
  additive; nothing from those sessions was reverted.

## Deviations

1. **AUR unavailable** — `sudo` needs a password here, so `yay -S` cannot run unattended. The prebuilt
   ai-memory release (sha256 verified against the published digest) and npm under a user prefix were used.
2. **MCP registered globally, not in `.omp/mcp.json`** — that file is git-tracked and the rendered entry
   embeds a bearer token. Writing it there would have committed a secret.
3. **Gateway client key is mandatory** — OmniRoute 3.8.50 requires a valid key on `/v1` regardless of
   `REQUIRE_API_KEY`.
4. **OMP reads `~/.omp/agent/models.yml`**, not `.omp/models.yml`; `bin/omp-kad` would symlink the latter
   into place but that path holds a stale regular file, so `bin/kad-models` projects into both.
5. **Plaintext HTTP on the LAN** with a bearer token, per the operator's chosen topology; Caddy TLS is the
   recorded upgrade path. The substrate bearer and the gateway key live only in mode-0600 files outside the
   repository.

## Security finding worth flagging

OmniRoute's default startup **binds `0.0.0.0` with no API-key requirement** and warns that the inference
plane is then reachable by any device that can route to the host, billed to the operator's configured
providers. On a machine holding a Google AI Pro subscription, an OpenCode Go subscription and an OpenRouter
key, that is an unbounded spend surface on the LAN. It was corrected to a loopback bind **before any
provider credential was registered**.

The dashboard's initial password is still the shipped default. It is loopback-only, so exposure is limited,
but changing it is a one-minute action worth taking.

## Addendum — commit hygiene pass (2026-09-11, post-acceptance)

Committed as `d05bf4f`, `8301de2`, `bda2085`, `5249489`, `534685d` (working tree clean afterwards, mirror
drift 0). Four defects were found while preparing the commit; three were introduced or left open by this
workpackage and one predated it.

**1. The published mirror was leaking the capture ledger.** `bin/kad-memory publish` rsynced the whole record
into `vault/`, which carried `log-YYYY-MM.md` — the substrate's live capture ledger. That file is
unbounded, regenerates continuously, and records raw session events **including prompt text**. `vault/` is
git-tracked and pushed to the KAD-PI remote, so this would have published session activity for no gain in a
clone. The ledger now stays in the record and out of the mirror.

**2. `--delete-excluded` was missing, so exclusion alone could never remove anything.** rsync treats an
excluded path as *protected* and will not delete it without that flag. The first attempt at (1) therefore
appeared to work while leaving the ledger in place — the mirror would have silently accumulated exactly the
files the exclude existed to keep out. With the flag, the mirror is a pure function of (record, excludes),
and a second publish is byte-identical.

**3. The generated bundle index advertised a directory that never ships.** ai-memory's `index.md` lists
`.obsidian/`, which the mirror deliberately excludes. A committed index pointing at a non-existent directory
is a broken link; publish now drops dot-directory entries.

**4. `.gitignore` would have allowed ~25 GB into a commit (pre-existing).** `.state/omp-kad/` was ignored but
the narrower pattern let `.state/backup_pre_etapa_a/` through, so `git status` never settled. More seriously,
nothing ignored `ACE-Step/` (19 G upstream clone), `tools/game-stack/emsdk/` (1.7 G, own `.git`),
`tools/game-stack/target/` (2.6 G Rust output), `tools/game-stack/godot-source/` (1.4 G, own `.git`) or
`tools/game-stack/exports/` (317 M). A single `git add -A` would have staged them. All are now ignored;
`tools/game-stack` contributes 32 authored source files instead of 6.1 G.

Also removed: `AGENTS.md.bak-<epoch>`, a backup emitted by the tooling that edits `AGENTS.md` in place. The
`*.bak-*` pattern is now ignored so the next run cannot leave one behind.

**Credential verification before commit.** Both live secrets (the ai-memory bearer token and the OmniRoute
key) were scanned for across every tracked and untracked file, and again across the staged diff:
zero hits. `.ai-memory/` — which holds the record, the config and the bearer in `env` — was already ignored.
The scratch files that held the gateway key and an authenticated dashboard session (`/tmp/newkey.json`,
`/tmp/omni-cookies.txt`) were purged with `shred -u`.

**Post-commit state:** ISA 33/33 PASS, 63 focused tests pass, `bin/kad-models sync` idempotent,
`bin/kad-memory status` drift 0, both services active.
