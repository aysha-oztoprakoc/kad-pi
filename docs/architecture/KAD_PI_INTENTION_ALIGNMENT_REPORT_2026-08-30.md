## 1. Executive Alignment Statement

`KAD-PI` is a local-first **Personal Engineering Operating System and Scientific Research Laboratory** for advanced computer-engineering projects. Its primary objective is to maximize the project lead's cognitive leverage and execution capacity to research, design, implement, verify, manage, and continuously evolve complex software and systems architectures.

KAD-PI coordinates deterministic developer tools, local and remote AI models, structured knowledge representations, and bounded autonomous execution agents while strictly preserving:
* **Human Strategic Sovereignty** (`AUTHOR_DECLARED`)
* **Typed Evidence & Mutator Independence** (`AUTHOR_DECLARED`)
* **Scientific Traceability & Reproducibility** (`AUTHOR_DECLARED`)
* **Resilient Local-First Autonomous Degradation** (`AUTHOR_DECLARED`)
* **Preservation of the Frozen Pre-GitHub Baseline (`WP-028`)** (`REPOSITORY_CONFIRMED`)

Automation in KAD-PI is not an end in itself. Automation exists to eliminate low-leverage supervision, mechanical context reconstruction, and repetitive debugging so human attention remains focused on architecture, high-value research framing, and critical trade-offs.

### Sovereign Constitutional Invariants:
1. **Model Proposes, Policy Authorizes**: Probabilistic model outputs are strictly proposals; deterministic code, tests, schemas, and human decisions authorize state changes.
2. **Lifecycle Separation**: `WORK_LIFECYCLE != EXECUTION_RUN_LIFECYCLE`. `bin/workctl` is the sole lifecycle authority; execution engines (OMP, Pi, Warren) only provide run receipts.
3. **Execution vs Learning Separation**: `EXECUTION != LEARNING`. Workers consume doctrine during execution; workers never mutate canonical knowledge in-flight.
4. **Epistemic Separation of Duties (Mutator Independence)**:
   $$\text{MUTATOR} \neq \text{SOLE VERIFIER} \neq \text{ACCEPTANCE AUTHORITY}$$
   Where $\text{MUTATOR} \in \{\text{kad-builder}, \text{kad-debugger}\}$. Any role that mutates state may provide evidence, but may never be the sole authority that verifies and accepts it.
5. **Typed Verification Precedence**: No single evidence class universally dominates all others. Verification must match the claim type:

| Claim Class | Authoritative Evidence Class |
|---|---|
| JSON / Data Schema Conformance | Deterministic schema validator (`checkSchema`) |
| Feature / Unit Behavior | Reproducible behavioral test suite (`node --test`) |
| Performance / Resource Utilization | Controlled benchmark profile with telemetry (`CONTROLLED_BENCHMARK_PROFILE`) |
| Security / Trust Boundary | Threat model test + policy check + adversarial probe |
| Literature / Domain Fact | Citation provenance check + multi-source triangulation |

### Maturity Pathway for Workpackage Admission:
* **New / Ambiguous Work**: Strict human review and explicit ticket import into `workctl`.
* **Repeated Bounded Work**: Deterministic policy admission verifying scope, owned paths, and test contracts.
* **Empirically Qualified Low-Risk Work**: Automated admission for routine deterministic projections (e.g. inventory rebuilds, linter autofixes).
* **Scope Classification for Discovered Work**:
  * *Within Scope & Required*: Subordinate task inside active workpackage.
  * *Out of Scope & Required for Acceptance*: `BLOCK` active workpackage + submit successor workpackage proposal.
  * *Out of Scope & Optional*: Backlog proposal, continue current workpackage.
  * *Security / Constitutional Anomaly*: Immediate fail-closed human escalation.

### Native Deterministic PM Core vs Interpreted Layer:
* **Deterministic Mechanics**: Owned paths, dependency edges, STC leases, lifecycle states, evidence hashes, and resource envelopes.
* **Constraining Path Analysis**: Dynamic `CURRENT_CONSTRAINING_PATH` analysis tailored for research-heavy workloads.
* **External PM Projections**: External tools (Jira, Linear, Gantt) are classified as `DEFERRED / OPTIONAL PROJECTIONS` rather than categorically rejected; they never acquire canonical authority over local `workctl`.

### Knowledge Promotion Policy `[AUTHOR_DECLARED: DEC_ID_06]`
* **Human Epistemic Sovereignty**: The human exclusively defines the epistemic policy and what classes of knowledge are eligible to become canonical.
* **Deterministic Policy-Bounded Promotion**: Deterministic tooling is pre-authorized to promote low-risk, verifiable records (e.g. pushed commit SHAs, generated inventories, validated schema definitions, test receipts).
* **Human Approval Gate**: Mandatory for architectural doctrine, governance policies, high-level research synthesis, and contradiction resolution.

### Impact-Scoped Contradiction Containment `[AUTHOR_DECLARED: DEC_ID_16]`
When deterministic linters or audits detect conflicting claims, they are classified by impact rather than triggering a global system halt:
* `INFORMATIONAL`: Annotates claims as `CONTESTED` without blocking execution.
* `OPERATIONAL`: Pauses specific automated workflows dependent on the contested fact.
* `EPISTEMIC`: Fails closed for research promotion touching the disputed domain.
* `CONSTITUTIONAL`: Immediately blocks privileged operations and alerts the human governor.
